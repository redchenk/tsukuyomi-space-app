# 原生眨眼后眼部发白

2026-09-27，用户在 macOS Flutter 原生窗口中报告：眨眼结束、重新睁眼的一瞬间，眼睛发白。

## 定位与改动

最初仅查看闭眼到睁眼的静态图和软件渲染，没有捕捉到问题。随后在 Mac 的实际图形后端连续渲染模型，保留眨眼前的物理更新，观察到睁眼后的眼部高光明显过亮；相同姿态的软件渲染保持正常瞳孔颜色。

原实现把每个网格的透明度放进 `ColorFilter.matrix` 的 alpha 行，并给所有网格使用颜色滤镜，遮罩也额外染白。现改为：

- 使用 `Paint.color` 的 alpha 表达网格透明度。
- 颜色滤镜只负责非默认 multiply/screen RGB 变换，alpha 保持原值。
- 遮罩只使用纹理原有的 alpha，移除无必要的白色变换。

修改后 Mac 的连续帧恢复正常瞳孔颜色。保留眼部原始物理、纹理与高光，没有通过关闭物理或替换模型隐藏问题。此结论基于本机实际渲染对照，未声称覆盖所有 Flutter 版本与图形后端。

同时将原先 180ms 的三角形眨眼曲线改为与网站一致的节奏：闭眼约 130ms、停留约 75ms、睁眼约 210ms，带周期抖动。透明度修正才是消除本次发白的关键；单独改变节奏时，原生帧中仍可见过亮高光。

## 验证

`test/live2d_renderer_test.dart` 校验白色纹理在 25% 透明度下的像素值，背景 RGB 为 `(20,30,60)`：

| 合成 | 期望 RGBA | 本机原生结果 |
| --- | --- | --- |
| 普通 | 79,86,109,255 | 一致 |
| 加法 | 84,94,124,255 | 一致 |
| 带遮罩加法 | 84,94,124,255 | 一致 |

Widget 测试不足以替代实际设备后端验证。可运行：

```sh
flutter run -d macos -t tool/verify_live2d_rendering.dart
```

工具在原生窗口显示像素检查结果，并在安装本地模型和 SDK 时绘制 30 张眨眼帧（5.500–6.467s），覆盖第二次完整眨眼与恢复过程。结果写入应用临时目录 `tsukuyomi-render-check/`，具体路径显示在窗口。普通源码克隆不带模型时，像素检查仍可运行。
