# 原生应用内更新 · 0.6.11+17

首次需要通过官网或 GitHub 安装 0.6.11；此前的应用不含更新器，不能自行获得这个入口。之后官方仓库发布新版本，应用即可发现并提示。

## 用户操作

1. 顶部导航的更新图标，或菜单 → **应用更新**，进入 `/app/update`。
2. 查看当前版本、新版说明、平台与安装包大小，点击 **下载更新**。
3. 下载进度实时显示；可以取消。断开的下载重新开始，完整下载的包在校验通过后可复用。
4. SHA-256 校验通过后，点击安装按钮，保存编辑内容并结束正在进行的任务，再确认打开系统安装器。

| 平台 | 应用内完成 | 系统中完成 |
| --- | --- | --- |
| Android ARM64 / x86_64 | 下载、校验、检查包名/签名/版本、调起安装器 | 首次允许“安装未知应用”；返回后再次安装，系统确认覆盖安装 |
| Windows x64 | 下载、校验、启动 Inno Setup | 安装器处理旧文件和正在运行的程序；完成后启动新版。便携版用户会安装为常规版本 |
| macOS Universal | 下载、校验、打开 DMG | 拖入 Applications，确认替换旧版并重新打开 |
| Debian / Ubuntu x64 | 下载、校验、打开 DEB | 系统软件安装器按系统权限提示完成更新；无图形安装器时按 GitHub 安装说明执行 |
| iOS ARM64 | 下载、校验、分享/导出未签名 IPA | 使用自己的证书和签名工具签名安装；不能直接在应用内覆盖安装 |

更新不卸载应用，不清除账号、聊天、文章草稿和模型配置。Android 调试版与官方发布包签名不同，不能直接覆盖；应用会说明这个原因。iOS 改变签名身份或卸载可能影响本机数据，应沿用原签名身份。

## 检查与性能

- Room 首帧后延迟 5 秒开始自动检查；回到前台可触发检查。成功检查后 24 小时内不重复请求；失败退避 1 小时。手动检查不受间隔限制。
- 只检查，不自动下载、安装或退出。用户可关闭自动检查，选择正式版/预览版渠道，或对某个版本选择“稍后提醒”；更高版本仍提示。
- 当前渠道使用编译内置 tag + 平台包信息，按 SemVer 排序，正确比较 `beta.10` / `beta.2`。拒绝降级、草稿、未上传文件、不匹配的下载地址、重复资产和缺少校验文件的发布。
- 元数据不超过 1 MiB；校验表不超过 64 KiB；安装包不超过 2 GiB。检查总超时 20 秒；下载连接超时 15 秒，数据空闲超时 30 秒，整体最多 20 分钟；取消关闭 HTTP 连接并清理自己的半成品。
- 安装包流式写入，最多约 1 MiB 缓冲；进度通知最多每 100 ms；哈希计算在独立 isolate 执行。更新状态仅刷新图标和更新页面，不订阅整个 Room。

## 来源与完整性

公开请求直接发往 `api.github.com/repos/redchenk/tsukuyomi-space-app/releases`；安装包和 SHA256SUMS 直接从官方 GitHub Release 下载，网站/CDN 不转发二进制。

只接受 HTTPS 官方 GitHub 和 release-assets/objects.githubusercontent.com 的重定向，最多 5 次；不发送站点 Cookie、用户模型密钥或 GitHub 令牌。SHA256SUMS 必须精确匹配文件名；存在 GitHub `digest` 时必须一致。安装前再次校验本地文件大小、路径和 SHA-256。Android 在请求安装权限或打开安装器前，额外核对当前包名、签名证书和递增版本号。

下载位于应用的私有缓存 `tsukuyomi-updates`。不接受符号链接，不使用任意外部路径；Android FileProvider 只开放这个缓存子目录，并授予临时只读访问。

## 后续发布

每次更新同时修改 `pubspec.yaml` 的版本/递增构建号及 `lib/core/app_release.dart` 的 tag。`tool/release/metadata.py` 在发布前强制校验二者与实际发布 tag 一致。保留现有完整五平台发布流程、安装说明、许可证和 SHA256SUMS；不用额外的更新后端或凭据。

需要升级验收时，在实际设备上用两个同签名、递增构建号的发布包完成旧版 → 新版，检查记录、配置、草稿保留及新版本再次检查无提示。CI 编译、下载与通道验证不能替代五个平台上的完整安装交互。
