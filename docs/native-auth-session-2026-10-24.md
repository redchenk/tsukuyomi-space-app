# 自动朗读、账号与 QQ 授权修复

用户通过邮箱或用户名密码登录后，中文聊天自动朗读提示“请先登录月读空间，再使用站内直供”，设置页头像也再次显示登录表单。

自动朗读的直接原因是 `AudioVoice` 在调用聊天模型翻译中文回复时只传入了 Cookie，没有传入 `LlmClient.siteAccountId`。主聊天请求有完整身份，因此聊天成功而随后的翻译被拒绝。新增回归先复现了相同错误，修复后沿真实 `SiteClient` 密码登录、`RoomController.send`、`AudioVoice` 翻译/官方 TTS、临时 WAV 文件与播放调用整条路径通过。仅 HTTP 与系统播放器使用替身；重播不重复创建任务，切换账号拒绝旧语音绑定，过期会话不发起翻译或合成。

另修复设置页头像无条件打开登录的问题；有效账号进入个人中心，游客或已过期会话继续打开登录。演示模式不再被当作未登录；保存官方语音保持当前聊天模式。授权会话通过主站核实后立即标记已认证，失败回退恢复原来的认证状态。

Android QQ 登录改为腾讯官方 SDK 3.5.19。QQ 互联已创建真正的移动应用 `1905926637`，包名和发行签名与 APK/备案一致。仅在用户点击 QQ 登录并单独同意后初始化 SDK，检查 QQ 客户端和 SSO 能力，拉起 QQ 后通过 Activity 回调取得授权结果。同源服务端以一次性 state、绑定 Cookie 和发起账号校验请求，再向腾讯验证 AppID、OpenID 与 token，生成本站会话；不把 AppKey 放入 App。网站与移动 OpenID 分别保存，新移动身份通过原生邮箱/已有账号表单完成绑定。iOS/macOS/Windows 暂保留原有网页授权容器和受限 QQ 官方 scheme 唤起；没有虚构这些平台的移动签名或 Universal Link。

创建时 QQ 平台显示“审核中”，提示七个工作日；审核中禁止修改调试 QQ，用户指定的两个号码尚未保存。代码验证完成也不能替代腾讯审核及 K90 真实授权。v0.6.29 先发布自动朗读及登录态修复，同时预置 SDK。配套服务端尚未上线，Android QQ 入口明确提示使用密码登录；真实 QQ 授权另待平台审核和服务端启用后验收。

原生入口、Hub 和通用页脚展示固定 App 备案号“苏ICP备2026030780号-3A”，离线可见，链接至工信部。2026-10-24 在阿里云已备案平台记录核对安卓包名 `space.tsukuyomi.tsukuyomi_space_app`、证书 MD5 `5870574F60B40E270CB4C9979B5FFD19`，与公开 v0.6.28 APK 的 v2 签名证书一致。保持原有发行签名；不添加没有官方依据的 Manifest 字段。

小米安装器备案识别属于系统侧校验。已备案仍提示时，按照[小米官方申诉指南](https://dev.mi.com/xiaomihyperos/documentation/detail?pId=1781)，在安装提醒中选择“填写申诉”；个人备案使用备案人身份对应信息，需用户在手机上完成敏感身份信息提交。不能通过改 App 里的备案文字保证系统提醒消失。

修复版为 `0.6.29+36 / v0.6.29-beta.1`，更新沿用阿里云北京分发。自动化不使用真实账号凭据、不创建真实计费任务；K90 的 QQ 唤起、实号回调、安装器提示和实际语音播放保留真机验收边界。本测试版的发布说明明确标注 QQ 原生登录暂不可用。

验证覆盖自动朗读整条调用、官方 SDK 方法通道、取消同意不初始化、账号切换停止授权、原生凭据换取会话/待绑定票据以及后端拒绝伪造身份和重复回调。正式 SDK 已通过 Android debug 与签名 release 编译；Flutter 回归 1051 项通过、41 项跳过，Android API 35 模拟器安装启动及原生探针通过。最终发行构建与下载校验另行记录；上游 QQ 响应和操作系统通道在自动化中使用替身。
