# 自动朗读、账号与 QQ 授权修复

用户通过邮箱或用户名密码登录后，中文聊天自动朗读提示“请先登录月读空间，再使用站内直供”，设置页头像也再次显示登录表单。

自动朗读的直接原因是 `AudioVoice` 在调用聊天模型翻译中文回复时只传入了 Cookie，没有传入 `LlmClient.siteAccountId`。主聊天请求有完整身份，因此聊天成功而随后的翻译被拒绝。新增回归先复现了相同错误，修复后沿真实 `SiteClient` 密码登录、`RoomController.send`、`AudioVoice` 翻译/官方 TTS、临时 WAV 文件与播放调用整条路径通过。仅 HTTP 与系统播放器使用替身；重播不重复创建任务，切换账号拒绝旧语音绑定，过期会话不发起翻译或合成。

另修复设置页头像无条件打开登录的问题；有效账号进入个人中心，游客或已过期会话继续打开登录。演示模式不再被当作未登录；保存官方语音保持当前聊天模式。授权会话通过主站核实后立即标记已认证，失败回退恢复原来的认证状态。

用户补充 K90 的 QQ 授权页会弹出内部窗口但无法打开 QQ。现有 WebView 只允许 HTTPS，因此拒绝 QQ 官方移动登录脚本发出的 `wtloginmqq://ptlogin/qlogin`。现按 QQ HTTPS 来源、登录 scheme/host/path 校验后调用系统启动，保留浏览器会话以等待网页授权完成。弹窗使用原生 windowId，保留 opener 和空白窗口后续跳转；未安装或系统拒绝启动时显示说明。仍拒绝任意 intent、分享链接和非 QQ 页面发起的客户端跳转。来源：2026-10-24 实际公开授权页加载的 `https://qq-web.cdn-go.cn/monorepo/3ea7b82c/ptlogin/js/login_10.js`。

原生入口、Hub 和通用页脚展示固定 App 备案号“苏ICP备2026030780号-3A”，离线可见，链接至工信部。2026-10-24 在阿里云已备案平台记录核对安卓包名 `space.tsukuyomi.tsukuyomi_space_app`、证书 MD5 `5870574F60B40E270CB4C9979B5FFD19`，与公开 v0.6.28 APK 的 v2 签名证书一致。保持原有发行签名；不添加没有官方依据的 Manifest 字段。

小米安装器备案识别属于系统侧校验。已备案仍提示时，按照[小米官方申诉指南](https://dev.mi.com/xiaomihyperos/documentation/detail?pId=1781)，在安装提醒中选择“填写申诉”；个人备案使用备案人身份对应信息，需用户在手机上完成敏感身份信息提交。不能通过改 App 里的备案文字保证系统提醒消失。

修复版为 `0.6.29+36 / v0.6.29-beta.1`，更新沿用阿里云北京分发。自动化不使用真实账号凭据、不创建真实计费任务；K90 的 QQ 唤起、实号回调、安装器提示和实际语音播放保留真机验收边界。最终测试与公开下载结果见本版本发布验证记录。

本机验证：静态分析通过；完整 Flutter 回归 1,044 项通过、41 项跳过，后补 QQ 原生窗口/系统启动回归 1 项通过；发布工具 40 项通过。QQ 回归驱动真实窗口导航回调并模拟操作系统启动结果，覆盖空白弹窗继承来源、窗口 ID、客户端启动失败时保留网页登录和关闭子窗口。
